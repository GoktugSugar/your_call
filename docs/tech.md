## Engine & tooling

## Stats system
- Display-only (never changes outcomes; the one exception is the coordination gamble, which resolves against a seeded crowd), offline-first, and optional.
- Data: ship with seeded numbers baked in, drawn from real survey data (for example MIT's Moral Machine for the classic dilemmas, and would-you-rather / preference survey splits for the lighter questions) wherever it exists, then blend toward real player responses as they accumulate. The baked-in seed doubles as the offline fallback. The crowd reveal is the central hook (see `gameplay.md`), so every shipped question needs a seed.
- Backend (deferred): a tiny global tally per choice. Use Supabase or a small serverless endpoint, not Nakama. Do not build this early; seeded data carries the whole prototype with zero backend.

## Data model
Each question is a self-contained `Dilemma` ScriptableObject (a `.asset`, class `Dilemma`; the class name predates the pivot to all question types, so a `Dilemma` asset is now the data unit for **any** question, from a light would-you-rather to a heavy dilemma) holding: `id`, `verb`, `weight` (`Light` / `Medium` / `Heavy`, which scales the consequence duration), `narratorPrompt`, and a list of `DilemmaChoice`. `DilemmaChoice` is a `[Serializable]` class (or a sub-asset) holding: `id`, `label`, `narratorReact`, `route` (which track the trolley runs, or which group is struck), `diverts` (does the choice throw the lever), `seedVotes` (display-only tally, needed on every question for the crowd reveal), and `profileImpact`. Unity does not serialise dictionaries by default, so `profileImpact` is a small serializable list of axis and value pairs (the axes in `narrative.md`), recorded silently; a **pure-taste question can carry no `profileImpact` at all** and exist just for the fun and the crowd stats. The first question is an asset under `Assets/Data/` (for example `Assets/Data/Trolley.asset`).

**Multiple-choice** (pick one of several) is **now built** (Chapter 1's Full Track): a `MultipleChoice` verb value with its own resolver and presenter (see below), carrying the everyday volume alongside binary. `DilemmaChoice` also gained `endsGame` (a general "this choice ends the run with an ending rather than the normal aftermath" flag, used by the baby opener). `Dilemma` gained trolley-presentation fields so one shared station serves many beats: `mainFigureCount` / `spurFigureCount`, optional per-track figure prefab overrides (`mainFigurePrefab` / `spurFigurePrefab`, for the baby), and an optional `spurPlea`.

Shared state (the profile) lives in a `Profile` service: a persistent singleton MonoBehaviour (`DontDestroyOnLoad`), or a runtime ScriptableObject if you prefer, holding a silent tally over the axes in `narrative.md`, never drawn during play. The axis set is broadening from the moral-only four to the wider "who you are" portrait in `narrative.md` (head vs. heart, self vs. others, and so on); widening the `MoralAxis` enum values to match is a small data follow-up (see `open-questions.md`), not a loop change. Every feel or timing value is a `[SerializeField]` on the relevant component so it can be tuned in the Inspector.

## Verb architecture (resolvers and presenters)
Each dilemma has a `verb`, and each verb maps to two seams so the loop stays generic as verbs accumulate:
- A `VerbResolver` (pure logic, `Scripts/Resolution/`): the player's choice plus the dilemma data (and, for coordination, the seeded crowd) produce a `DilemmaOutcome` (which party ids fold, the narrator reaction to show, and a `ResolutionReport` for the stats). `BinaryResolver` (the trolley) and `CoordinationGambleResolver` are built; `AllocationResolver` and `SelfSacrificeResolver` are stubbed seams. `VerbResolvers.For(verb)` is the only place the verb-to-resolver mapping lives.
- A `ConsequencePresenter` (a MonoBehaviour, `Scripts/Consequence/`): owns the verb's scene apparatus (figures, diegetic input, the animated consequence) and raises `Chosen` for a diegetic pick. `TrolleyConsequence` (track, trolley, lever; the struck group folds on impact), `RoomConsequence` (a seeded room and one distinguished charge, plus the two ink buttons; only the charge folds when the gamble fails, while the room stays standing), and `ShootingConsequence` (the man and the last bear stand apart in the void, aimed at with a first-person crosshair; the shot party folds; the man and bear are sized via an exposed scale, and the **imp is an optional third target** whose shot raises an `ImpShot` event for the secret ending). All three reuse the shared fold-and-fall; the shooting station also reuses `BinaryResolver` unchanged.

`DilemmaStage` holds a resolver (looked up by verb) and a `ConsequencePresenter` reference (assigned per scene) and never branches on verb: it presents, arms the presenter's diegetic input plus an optional text fallback, resolves, plays the consequence, reveals the stats from the report, and records the profile silently. Adding a question is a new asset; a new verb is a new resolver, a new presenter, and one line in `VerbResolvers`, never edits to the loop.

**Multiple-choice** is built this way: `MultipleChoiceResolver` (the pick decides the outcome, like binary but over N options; reflective N-bar stats) plus one line in `VerbResolvers` and a `MultipleChoice` value appended to `DilemmaVerb` (existing indices unchanged). Its presenter is `ThreeTrackConsequence` (Chapter 1's Full Track): a three-track apparatus drawn in the ink style from the shared `Trolley`, `Figure` and fold-and-fall, which owns its three diegetic pick options (each track's ink label, picked by click or the 1/2/3 keys), so the beat needs no text fallback. The loop, stats, and profile seams are reused; `DilemmaStage`/`DilemmaRunner` never branch on verb.

New `DilemmaChoice` fields for resolution: `struckParty` (a party this choice always strikes) and `gambledParty` (a party struck only if a coordination gamble fails), plus `narratorReactStruck` (an outcome-aware reaction). New `Dilemma` fields: `statsHeading`, and for coordination `crowdSafeFraction`, `crowdThreshold`, `thresholdLabel`. `StatsView` is driven by the `ResolutionReport` and draws an optional threshold marker, so a coordination gamble's number reads as load bearing (the line the crowd had to cross) while the trolley's stays reflective. The coordination gamble is rendered in the monochrome ink language, told apart by form, pattern, and label, not colour (`art-and-ui.md`), with amber only on hover, selection, and consequence.

## Chapter 1 tech (the tracks)
Chapter 1 (see `gameplay.md`) is mostly new **data plus imp copy** over the reused systems; the code additions are small and general.
- **One shared trolley station.** `TrolleyConsequence` now tears down its previous figures and rebuilds per beat, and reads per-`Dilemma` `mainFigureCount` / `spurFigureCount`, `figuresBranded`, an optional per-track figure prefab (`mainFigurePrefab` / `spurFigurePrefab`), and an optional `spurPlea`, so a single station runs the baby opener and trolley beats 1 to 5, 7 to 9. `Track` gained count-driven `MainFigurePositions(count)` / `SpurFigurePositions(count)` and `GetPath(route, mainCount)` (an empty main runs on down the line, for the Dark Track); `Lever.ResetSwitch()` resets the switch for reuse. The Dark Track and Full Track get their own stations.
- **The multiple-choice / three-track apparatus.** `MultipleChoiceResolver` + `ThreeTrackConsequence` (see the verb section above).
- **The Dark Track** (beat 6) is a dedicated `DarkTrackConsequence` (`Scripts/Consequence/`): only the branch is real; the main track is empty and covered by a dense dark ink **shroud** (a scribbled mass); after the choice resolves it plays an **after-choice reveal** (the shroud dissolves to the empty rail) and the imp savours it. Reuses the `Track`, `Trolley`, `Lever`, `Figure`, `BinaryResolver`, and fold-and-fall.
- **The floating plea** (beat 5) is `FloatingFigureText` (`Scripts/Narrator/`): a short line of ink floated over a figure with no bubble, box, or background (the menu-bark treatment), shown by `TrolleyConsequence` over the lone branch soul when the dilemma carries a `spurPlea`.
- **On-model figures.** `Figure` was refactored to an extensible base: a `protected virtual BuildShape()` seam and a multi-stroke list, with its default single stick stroke unchanged, so it still inks, brands, folds and fades as one unit. `BabyFigure` and `PregnantFigure` (`Scripts/Figure/`) subclass it and override only their shape (a clearly-a-baby doodle; a rounded-belly figure), inheriting everything else; the three-track child is a scaled `Figure` (no new class). All are minimal ink, no detailed or creepy faces (`art-and-ui.md`).
- **The choice-triggered ending** (the baby opener). `DilemmaChoice.endsGame` marks a choice that ends the run. `DilemmaRunner` takes an optional ending handler and, after the consequence of an `endsGame` choice plays, hands off to it instead of the normal reaction and stats; `DilemmaBeat` supplies the handler (an optional `Ending` ref) that plays the imp's break line (the choice's `narratorReact`), fades the imp, and rolls the credits, reusing the existing `Ending` + `CreditsRoll` untouched. It is the same shape as the shoot-the-imp ending, out-of-band from the generic loop, with no verb branches. Leaving the ending ref empty (every normal beat) makes `endsGame` a no-op.

## Chapter 3 tech (the money)
Chapter 3 (see `gameplay.md`) is a scene reusing the sequence layer and the button-chapter's self-contained-beat pattern; the code is a small money service, one shared priceable-beat component, the special-flow beats (poverty refund, auction, and the closing read), and a batch of coloured doodles. `DilemmaStage` / `DilemmaRunner` stay generic; every money beat is a `SequenceBeat` the `SequencePlayer` plays in order, and no bespoke branches are bolted into unrelated systems. The chapter was **reworked for scarcity**: the board was repriced so its total is several times the 10000 pot (a run buys only roughly a quarter to a third), the two throwaway beats (the 2 dollar nose and the flat extra year) were cut, **ten new double-edged items** and a **deadpan cucumber finale** were added, a **recurring finale tease** was seeded across beats, the **cash-out shop was removed** in favour of a lean read beat, and the **cigarette auction was rewritten** (a real auction that never deducts money). All prices and the pot are `[SerializeField]`.
- **The money/balance system.** `MoneyBalance` (`Scripts/Money/`) is a chapter-scoped scene object holding the finite pot: a `[SerializeField] _startingAmount` (10000, tunable), the running `Balance`, and `CanAfford` / `Spend` / `Refund` plus a `BalanceChanged` event. It also **draws the readout it owns** (a muted "balance" caption over the amount in amber, via `InkText`), fades it in on `Start`, bumps it on every change, and registers a renderer-bounds `ScreenKeepout` so the roaming imp stays clear. It is handed to the beats on the `SequenceContext`: a new **optional** `Money` field (null in every other chapter), so `SequenceContext` and `SequencePlayer` each gained one nullable `[SerializeField] _money` and nothing else changed. Amounts route through `Localization.Money`, so the balance and every price read in the active culture. It is chapter-scoped, not a persistent service; other chapters carry none and are byte-identical.
- **The shared priceable-beat component.** `PriceableBeat` (`Scripts/Sequence/Beats/`) is the workhorse for the plain beats and two of the specials, configured entirely by `[SerializeField]` data (the imp's pitch, the price, the thing's coloured `DoodleKind`, the seeded bought/passed split, and an optional silent profile axis + buy/pass nudges), so **adding a priceable beat is a new GameObject plus its doodle, not new code**. It draws the doodle (via `InkDoodle`) and a price tag, offers buy/pass through the shared `ChoiceButtons` as **plain text choices** (the `InkButton` was removed from the money beats: they read fine as text and the coloured doodle carries the visual, which also centres the composition), spends through the `MoneyBalance`, plays a light amber `InkPoof` consequence on a buy, then reveals the seeded split on the shared `StatsView` and records the silent `Profile`. It exposes `Bought` and `AmountSpent`. It also carries an optional `_teaseLine` (see the finale tease below). Three `_mode`s (an enum):
  - **Fixed**: a set price (free food, no more pain, the deleted memory, the cheap forgetting, the truth, and each of the ten new double-edged items and the cucumber). If the player is **broke** (after ending poverty) the buy is disarmed and the imp needles the empty wallet, resolving as a pass.
  - **EntireBalance**: the price is the whole current pot read at runtime (End Poverty, the opener that costs everything). `Bought` / `AmountSpent` feed the refund branch.
  - **Bulk**: priced per unit, buy as many as you like (a running tally shown) until the player stops or cannot afford another, capped by `_bulkMax`. The per-unit price can **climb** by `_bulkPriceClimb` each buy (0 = flat); the stranger's years use it at 0 (flat). The buy-a-year-for-yourself item that used the climb was **removed**, so nothing currently climbs, but the capability stays for a future bulk item. One component, no bespoke loop.
  The **localized food brand** is data: an optional `_brandKey` substituted into the pitch as a `{1}` slot (localized before filling, Chipotle → its own per language), plus an optional per-language doodle swap (`_altDoodleKind` + `_altLanguage`, so English draws a burrito and Turkish a kebab). Adding a language's food is a doodle and a brand key.
  - **The double-edged items and the cucumber are pure data.** Each is a `PriceableBeat` GameObject configured with its pitch, buy / pass / broke reactions, price, coloured `DoodleKind`, seeded split, and a short `_itemName` for the receipt and the buyback (The Good Luck, Charisma, Ten More IQ, Never Tired, The Lie Detector, Perfect Memory, One More Voice, Feel Nothing, Rewind, and the 100 dollar cucumber). Two items were **cut**: the **Off Switch** (Feel Nothing covers that ground; its `OffSwitch` drawer is dormant) and the **buy-a-year-for-yourself** item (the bulk stranger-years is the life-buying beat; the `_bulkPriceClimb` capability it used stays, now unused). No new code beyond the tease / climb / itemName fields: they are scene GameObjects with new copy and doodles. The cucumber uses custom bought / passed labels; the copy carries the imp's deadpan (it is just a cucumber, he will not explain).
  - **The recurring finale tease.** An optional `[SerializeField] _teaseLine` on `PriceableBeat` is shown (choice independent) after the beat's buy / pass reaction if set, so the imp dangles the big thing coming at the very end. It is **seeded as data on a handful of beats** (free food, the good luck, ten more IQ, the lie detector, one more voice, the truth), escalating in hype, so placement and wording are pure data. The cucumber then deflates it.
- **The mid-chapter buyback (`BuybackBeat`), which absorbs the poverty refund.** One beat, placed roughly midway (after No More Pain). Self-contained (`Scripts/Sequence/Beats/`), one job: repurchase owned items. It snapshots `ctx.Ledger.Bought` and, if empty, makes a quick remark and yields. Otherwise it draws the owned items as a list (each a small `InkDoodle` + name + the buyback offer in amber, reusing the receipt row style), then walks them one at a time: it highlights the row, the imp offers it (a spoken line with the item name and offer, poverty its own dark line), the player picks Sell or Keep via the shared `ChoiceButtons`. **Sell** → `MoneyBalance.Refund(offer)` (the money returns and the balance readout bumps), `PurchaseLedger.RemoveBought(name)` (they no longer own it, so it also drops off the end-of-chapter receipt), the row fades out, a light silent profile nudge (self), and the imp mocks. **Keep** → the row dims back, the imp mocks. The buyback offer is **data**: a `[SerializeField] _buybackFraction` (0.5, half back, so selling is a real loss) with a separate `_povertyBuybackFraction` (1, the whole pot back), rounded to `_roundTo`. A seeded sold-vs-kept split closes it. **Poverty is one entry in this list**, detected by its doodle (`DoodleKind.Poverty`): selling it hands the whole pot back and re-starves the children (the old refund's framing, as its `_povertySellPrompt` / `_povertySellReact`); keeping it holds. The standalone `PovertyRefundBeat` was **removed from the chapter** (its scene GameObject deleted; the class is left dormant in the repo), so there is one buyback system, not a separate poverty mechanic. It reuses the `MoneyBalance`, the `PurchaseLedger`, InkDoodle / InkText, the narrator, the ChoiceButtons and the silent Profile; `DilemmaStage` / the sequence stay generic. Buyback is kept to this single beat by design, not scattered as money tricks through the chapter.
- **The cigarette auction (`AuctionBeat`), reworked.** Self-contained (`Scripts/Sequence/Beats/`), reusing the `MoneyBalance`, the `WalkingButton` figure (its walk and its floating voice) and the reusable `Ending` + `CreditsRoll`. It draws its own cigarette doodle and climbing-bid readout and offers buy/pass as **plain text choices** (no `InkButton`); on a **pass** it mocks lightly and ends. On a **buy attempt** it instantiates the walking button off-screen on the right, `ComeAlive`s it and walks it in as the rival, then runs a rigged auction that the player can never win. **It is a real auction, so no money is ever deducted:** `AuctionBeat` never calls `MoneyBalance.Spend`, so the pot is intact whatever happens (the fix for the old bug where bids were permanently taken). The bids only climb, by a **fixed increment** (`_bidIncrement`, default 10): the player's opening bid is `_cigarettePrice` (20), the button counters +10, the player would bid +10 again, and so on (20 / 30 / 40 / 50, tunable). Each round the player picks **Bid {next}** or **Drop out**. **Drop out** → the button `WalkOff`s with the pack, the player keeps their whole pot (nothing was taken), the imp mocks losing to a button, a seeded split, end. **Keep bidding** past `_persistenceRounds` (default 3, counting the opening bid) → the imp **cuts the auction off** (he has seen enough) and `PersistenceEnding` fires the **secret ending**: the button gloats and walks off anyway, and the imp, exasperated that the player would chase this forever for nothing, plays the resurrect-then-cancer rage line through `Ending` (imp fades, credits roll). The game's **fourth** choice-triggered secret ending; the sting is that it cost the player nothing. The button's **first (arrival) and last (gloat) lines hold for `_voiceReadHold`** (longer than a mid-auction taunt) so they read clearly. `_cigarettePrice`, `_bidIncrement`, `_persistenceRounds`, `_voiceReadHold` and every timing are `[SerializeField]`; the copy (bid prompt, taunts, the imp's cut-in line, the rage line) lives in the code defaults. If the player is already broke when they try to buy, the rival never appears (the imp needles the empty wallet, it ends like a pass). See `open-questions.md` for tuning the increment and persistence threshold.
  - **Layout (no collisions).** The **pack and its price/bid readout sit left of centre** (`_packPosition` / `_priceTagPosition`), the **imp eases to a left-side spot** (`_impAuctionSpot`, `_impMoveDuration`, via a small `MoveImpTo` that lerps the imp's root transform while its idle life rides on its child rig, so the two never fight) when the auction opens and delivers from there, and the **rival stops well to the right** (`_rivalStop`, entering from the right) so its floating voice never overlaps the cigarette visual or the imp. All positions are `[SerializeField]`.
  - **Markup-aware floating voice.** The rival's floating voice now routes through `InkMarkup.ToRichText` (localize then markup), exactly like the narrator, so its `[amber]` bid amounts render as colour instead of printing the tags as literal characters. The same one-line fix was applied to Chapter 2's `WalkingButtonBeat.ShowVoice`, the shared floating-voice pattern, so neither can ever leak raw tags in any language. Every other Chapter 3 readout (the balance, the price tags, the tally, the item labels) is plain money or plain text with no tags; the imp's pitches and reactions already went through the narrator's `InkMarkup`.
  - **Bid readout cleanup (no stray amount).** The bid readout is torn down on every exit, including the secret ending: `PersistenceEnding` fades and destroys the readout before the rage line, so no leftover amount is left floating mid screen between beats or into the ending.
- **The purchase ledger.** `PurchaseLedger` (`Scripts/Money/`, a plain run-scoped service, not a scene object) records what the player bought and skipped so the overview can list it: `SequencePlayer` creates one whenever a chapter has a `MoneyBalance` (null everywhere else) and hands it to the beats on the `SequenceContext` (a new nullable `Ledger`). Each `PriceableBeat` records a buy (its `_itemName`, its doodle, the amount, and a count for bulk) or a skip (the price passed on); the poverty refund calls `RemoveBought` when the refund is taken, so a bought-then-refunded End Poverty is not shown as a purchase. The auction records nothing (no money changes hands).
- **The end-of-chapter overview / receipt (`ChapterOverview`).** The last money beat, replacing the standalone read (`MoneyReadBeat` is left dormant in the repo; the cash-out shop / `CashOutBeat.cs` was already dormant). One job: read the player from a receipt. It reads the run's `PurchaseLedger` and the `MoneyBalance` and draws, in the ink style, a receipt using the **item doodles**: a title, a row per bought item (small `InkDoodle` + name + amount in amber, a count for multi-buys, the dearest first if it must truncate to `_maxRows` with an "and N more" line), an ink rule, the money summary (started / spent / left), and a lighter row of the dearest few **skipped** doodles. It registers a renderer-bounds `ScreenKeepout` so the roaming imp stays clear, fades the whole receipt in, has the imp deliver a hoard / spend / middle **read** over it (choice independent) and fold the hoard ratio silently into `Profile` (self-vs-others, hoarding leans self), then fades out and the `SequencePlayer` fades to black. Every layout value, the copy, and the profile thresholds are `[SerializeField]`; it reuses `InkDoodle` / `InkText` / `InkLine` / the narrator / the profile. Built as its own component, scoped to Chapter 3 but reusable in spirit (a future chapter could show its own summary).
- **The coloured doodles.** `DoodleKind` gained the money-chapter drawers, each a small parametric drawer in `InkDoodle` with a matched `DefaultColorFor` outline colour (a coloured line not a fill, exactly like the would-you-rather doodles): the kept `Poverty`, `Burrito`, `Kebab`, `Bandage`, `MemoryCloud`, `StolenYears`, `Forgetting`, `CigarettePack` (and the dormant `Coin` / `Star` / `Candy`, `Nose`, `Hourglass`, `Tombstone`, kept for enum-ordinal stability), plus the new drawers: `Charisma` (**a pair of sunglasses**, redrawn from a haloed figure that read poorly), `IqUp` (**a brain**, a bumpy lobed outline with a centre divide and folds, redrawn from an up-arrow head), `CigarettePack` (**redrawn** as a cleaner flip-top pack with two cigarettes peeking out, the old messy box replaced), `PerfectMemory` (a head etched with sharp lines), `LieDetector` (an eye), `Rewind` (a curved back-arrow), `NeverTired` (an eye and a crossed-out z), `Clover` (a four-leaf clover), `FeelNothing` (a flat-mouth face), `InnerVoice` (a head with a speech curl), `Cucumber` (a cucumber), and `QuestionMark` (a plain question mark, replacing the tombstone for the truth beat). `OffSwitch` (a head with a toggle) is now **dormant** (its item was cut). New enum values are **appended** so existing scene ordinals never shift. Adding one is a value plus its drawer.
- **The scene and the hand-off.** `Assets/Scenes/ChapterThree.unity` (`SequencePlayer` as root, duplicated from `ChapterTwo` for the persistent cast plus a `MoneyBalance` wired to `SequencePlayer._money`). Beat order (24 beats): the reused `VoidWakeBeat` + `ImpAppearBeat` intro and an `ImpLineBeat` framing the pot, then **End Poverty, Free Food, The Good Luck, Charisma, Ten More IQ, Never Tired, the Cigarette Auction (mid-chapter), The Lie Detector, Perfect Memory, No More Pain, the Buyback (`BuybackBeat`, midway), One More Voice, the Deleted Memory, Feel Nothing, Rewind, the Bulk stranger-years, the Cheap Forgetting, the Truth (question mark), the Cucumber finale, the Overview receipt (`ChapterOverview`),** and a short `ImpLineBeat` closer (a light-to-heavy wave; the standalone Poverty Refund and the buy-a-year-for-yourself item removed, the Buyback added, and earlier the Off Switch / standalone read / Nose / Extra Year / Cash-Out already gone). `ChapterThree` is in Build Settings and `DevChapterPicker` (which lists beats live, so no picker edit is needed). The auction reuses the scene's own `Ending` and the shared `WalkingButton.prefab`. All copy is authored inline (English source of truth) and localized via the overlay layer; the Turkish for the whole chapter (the items and their receipt names, the auction copy, the buyback, and the overview) ships in `tr.json`, idiomatic and a first pass wanting native review (see the Localization section and `open-questions.md`).

## Would-you-rather breathers (the illustrated light beats)
The light would-you-rather palate cleansers (see `gameplay.md`, `art-and-ui.md`) are a reusable, data-driven beat sprinkled between the heavy beats in both chapters, and future ones.
- **`WouldYouRatherBeat`** (`Scripts/Sequence/Beats/`) is a self-contained `SequenceBeat`. It takes a `Dilemma` (Binary, weight Light) for the prompt, the two option labels, the seeded split, the per-side reactions and any (usually absent) profile impact, reads the two option doodles off the same asset, draws the **two doodles plus labels side by side** with an `or` between, and owns the diegetic pick (click a doodle or its label, or key 1/left and 2/right). It then **reuses `BinaryResolver`** (via `VerbResolvers`) for the reaction and the reflective how-others-chose report, the shared `StatsView` for the reveal, the silent `Profile` for any impact, and an `InkPoof` **amber** flourish on the chosen side. Snappy: no station, no elaborate consequence, no text fallback (the labelled doodles are the pick). `DilemmaStage` / the sequence stay generic. `_inkMaterial` and `_font` are the only per-beat wiring; everything else is data.
- **The doodles.** `InkDoodle` (`Scripts/Doodle/`) is one reusable component that draws a small on-model ink doodle from the shared strokes (`InkLine`, the same material, weight and boil, and it inks in and out like a `Figure`), selected by a `DoodleKind` (`Scripts/Doodle/DoodleKind.cs`): a switch of small parametric drawers (a poop swirl, an ice cream cone, a winged figure, a flexing figure, a giant duck, a little herd of tiny horses, a rewind button, a pause button, a snowflake, a sun, a three-armed figure, a two-headed figure). `Dilemma` gained two `DoodleKind` fields (`_optionADoodle` / `_optionBDoodle`, default None, ignored by every other verb), so a would-you-rather is fully defined by its data asset. Adding a NEW doodle is a new `DoodleKind` value plus its drawer; adding a would-you-rather that reuses existing doodles is pure data. Each doodle also has a **matched outline colour** (`InkDoodle.DefaultColorFor`: the snowflake ice blue, the sun orange, the duck green, the poop and horses brown, the ice cream pink, and so on; new `Palette.InkGreen` / `InkOrange` / `InkSky` / `InkPurple` alongside the existing brown / pink / blue / red), a **coloured ink line, not a fill**; `Dilemma` gained optional `_optionAOutline` / `_optionBOutline` `Color` overrides (default clear, alpha 0 = use the doodle's own colour), so a question can recolour per option as data. `WouldYouRatherBeat` colours each doodle with the override if set, else the kind's default.
- **The pool and the interleaving.** The pool is a set of `Dilemma` assets under `Assets/Data/` (Binary, Light): `WyrShitIcecream`, `WyrRewindPause`, `WyrColdHot`, `WyrArmHead`, plus the two existing light questions **folded into the format** by adding their doodles, `LightWarmup` (fly / super strength) and `LightBreather` (giant duck / tiny horses). All are stats-only (no `profileImpact`), seeds chosen to divide. Each breather is a `WouldYouRatherBeat` GameObject in a chapter's `SequencePlayer` beat list, so interleaving is **data-driven and reorderable, not hardcoded per spot**. `Opening` (Chapter 1) plays four (the warm-up and the breather at their old spots, replacing the retired text-only light `DilemmaBeat`s, plus a shit-or-ice-cream after the Passenger and a rewind-or-pause after the Reformed and the Cruel); `ChapterTwo` plays two (a cold-or-hot after the timer, an arm-or-head after the better offer). The old `LightChoiceConsequence` text-choice light presenter is superseded for these and left in the repo.

## Sequence layer & the imp
The opening (and, later, the campaign) is played by a small, general **sequence layer** (`Scripts/Sequence/`), built to extend to many dilemmas with narration between them rather than hardcoded to the opening:
- `SequencePlayer` (a MonoBehaviour) holds the persistent cast (the imp and its `NarratorView`, the shared `StatsView`, `ChoiceButtons`, `Profile`, camera, and a `ScreenFade`) and plays an ordered `List<SequenceBeat>`, handing each beat a `SequenceContext` with those shared pieces. It owns the order, not the beats' logic. As the **first step of entering every beat** it calls `ResetSharedUiForBeat`, a general lifecycle guarantee that instantly hides the shared `ChoiceButtons` (`ChoiceButtons.HideNow`, no fade) and clears the narrator, so choice options or leftover text from one beat are **never visible during the next**. This fixes the beats that pick via a diegetic button (the money-for-a-life meta button, the better-offer swap) and used to leave the shared choices up until the next beat re-presented; those beats also dismiss the choices on pick now.
- `SequenceBeat` is the abstract beat (`IEnumerator Play(SequenceContext)`); each concrete beat is a small single-purpose component (`Scripts/Sequence/Beats/`): `CrashFlashBeat` (the impressionistic death flash over a `ScreenFade`, ending on black), `VoidWakeBeat` (coming to as point of view: the black wash clears unevenly and the camera drifts and settles, no figure), `ImpAppearBeat` (the imp scribbles into being), `ImpLineBeat` (one or more imp lines, data-driven, auto-paced with a click to hurry), `FigureFadeBeat` (a general tool to ink a figure in or out between beats), and `DilemmaBeat` (runs one dilemma). The player is never rendered as a figure (first-person point of view), so there is no avatar beat.
- **The loop is reused, not rebuilt.** The per-dilemma loop (present, choose, consequence, stats, wait for advance) was extracted from `DilemmaStage` into `DilemmaRunner` (`Scripts/Dilemma/`, plus a `DilemmaTiming` bundle) with no behaviour change. A standalone one-dilemma scene keeps a thin `DilemmaStage` that runs the runner once and reloads; a `DilemmaBeat` activates its verb's **station** (the apparatus GameObject, which starts inactive), runs the same runner over the shared services, then lifts the tableau (`StatsView.Hide`) and clears the station for the next beat. No verb branches, no loop duplication. In the aftermath the runner sequences the two screens so they never fight: the imp's reaction plays over the world, then a **click gate** holds (the consequence beat owns this continue click; `ReactionHold` in `DilemmaTiming` is its lockout against a carried-over click), the reaction clears, and only then does the stats panel present and take sole ownership of the dismiss input, so the choice lands before the room's verdict.
- The imp is `ImpFigure` (`Scripts/Imp/`): a small black-ink devil drawn from ink strokes like the `Figure`/`Trolley`, with a scribble-in pop and a continuous idle life (a slow bob, a gentle rocking lean, and a subtle breath) that grows into a nod-and-lean gesture while a line inks on (it listens to a small `NarratorView.Speaking` event). Its size and every idle value are exposed `[SerializeField]` tunables. Pure ink, no amber by default; its single ink colour is one exposed `ImpFigure._color` that drives every stroke, so it recolours from one place, and it is **temporarily set to amber** on the opening's imp as a revertible experiment (see `decisions.md` and `open-questions.md`). Its face is an optional **expression set** behind a single master toggle `ImpFigure._useExpressions` (off by default, keeping the original single face exactly): on, the eyes and mouth become three re-pointable ink strokes and `SetExpression(ImpExpression)` swaps a small on-model set (grin, wide grin, smug, glare, surprised); the code is self-contained so the feature drops cleanly if unwanted. The menu imp has it on (a bark can carry a face); the opening and dilemma imps keep it off. The smug expression's mouth was dropped for a clean gap below the eyes, and the imp's **head is raised a touch** (`ImpFigure._headRaise`, small and tunable) so it sits on the body with a clean minimal neck join rather than overlapping it, applied to the imp itself so it reads the same wherever the imp appears. `ScreenFade` (`Common/`) is the one full-screen wash, used to open the game on black; the waking beat clears it into the void. The `Figure` has a hidden-start plus an ink-alpha setter for inking a figure in or out without folding (a general capability).
- The imp **repositions once per dialogue box**, then holds: `ImpRoamer` (`Scripts/Imp/`) listens to `NarratorView.PageChanged` and, on each new line or page, hops (quick, springy, eased) to a fresh spot and settles there to deliver, apart from its idle life. It never lands on content: it scores candidate spots by their clearance from every active `ScreenKeepout` (`Common/`) and takes a clear one, and if content appears over it (a station activating, the stats revealing) it hops clear. The keep-out for a dilemma station is the **real world bounds of its renderers** (`ScreenKeepout` RendererBounds mode), so the region tracks the actual trolley, track, figures, room and buttons rather than a guessed rect; the dialogue box and the stats content declare fixed rects. Beyond those live keep-outs the roamer also holds a **persistent centre keep-out** (a `_avoidCentre` toggle plus a tunable `_centreKeepout` world rect, both `[SerializeField]`), folded into the same clearance test, so the imp stays in the **side wings** even when the centre is empty (between beats, or on a light question with little on screen) and never drifts into the centre stage where the action and the player's eye belong. It applies wherever the imp roams (the opening and the menu), and the default rect leaves the wings free. Roam bounds, minimum clearance, and hop feel are exposed tunables; the local liveliness stays on `ImpFigure`. On the **main menu** it hops between barks the same way as the campaign: an `_autoHop` flag is off there (so it does not hop on its own on `PageChanged` or restlessly), and the barker calls `HopToNewSpot()` after a bark clears, running the same springy eased hop (`Reposition` → the `Hop` coroutine) to a fresh keep-out-clear spot, so the menu imp travels across the page with the campaign feel. (The instant `Teleport()` and its `InkPoof` (`Common/`) are now unused, kept in the repo.) The opening keeps `_autoHop` on and auto-hops on each new box as before.
- Narration is framed by a `DialogueBox` (`Scripts/Narrator/`): a rounded hand-drawn ink frame (softly rounded corners, faint paper fill, a border kept alive by a slight controlled wobble) that **floats clear of the bottom edge** — it computes its own position from the camera's bottom edge plus an exposed bottom offset and places the narrator's text with it. The reworked `NarratorView` types inside it, **centred** (horizontal centre, vertical middle) in the **Caveat** TMP font asset (`Assets/Fonts/Caveat SDF.asset`, built from the TTFs in `Assets/Fonts/Caveat/`, wired through an exposed `[SerializeField]` font slot). It **pages by whole sentences**: `BuildPages` splits the marked-up line into sentences and packs as many as fit the box (measured with TMP `preferredHeight`) onto each page, never splitting a sentence across two boxes; a click or key turns the page. Typing is reliable and does not shift: the whole page is laid out once, then its glyphs are revealed in place by raising their vertex alpha only (never re-laying-out), so the centred text never moves a pixel while it inks on. Each page reveals one glyph at a time and a click only finishes it after a short skip-lockout, so a click carried over from the previous box can never make a page appear instant; `Typed` fires once per real glyph (tags skipped) so the blip voice stays exactly in sync, both bracketed by `Speaking`. The box is sized with a little slack so the handwriting reads easily. The imp repositions per page (`PageChanged`), and authored emphasis tags become palette colours via `InkMarkup` (`Common/`) before rendering. The choice affordances (`ChoiceButtons`) sit above the box, never over it. The standalone one-dilemma scenes keep a top-anchored caption in the same Caveat font, sized tall enough that their prompts fit one page. The **main menu** shows the imp's barks not in the bottom box but as **plain floating ink text over the imp**, via `FloatingBarkText` (`Scripts/Narrator/`): it positions the reused `NarratorView` text above the imp (or below if there is no room), clear of the screen edges and the central menu content, with **no bubble, box, tail, or background**, just the words on the paper. It measures the wrapped text with `NarratorView.MeasureWrapped` (a pure `GetPreferredValues` measure that does not disturb the typewriter) to place it and reuses `SetTextArea` for the wrap width. The menu has no bottom dialogue box. (The earlier `SpeechBubble` frame was retired from the menu path and is now unused anywhere; the class is left in the repo.)

## Audio
- **The player's saved volumes drive the audio.** The `GameSettings` service (see the settings section below) holds a **music volume** and an **SFX volume** (0..1, persisted in `PlayerPrefs`). `MusicPlayer` scales its mix level by the music volume and follows it live (via `GameSettings.MusicVolumeChanged`); `ImpVoice` and `GunSfx` scale their per-shot level by the SFX volume (`GameSettings.SfxScalar`). All reads are null-safe (scalar 1 when there is no `GameSettings`), so the standalone dilemma scenes still play at full. The volume settings stay a mix ceiling, so the music still "sits under everything" at the setting's max.
- `MusicPlayer` (`Scripts/Audio/`): a small guarded singleton (`DontDestroyOnLoad`) that plays one looped background track quietly (a low default mix level, exposed) and does not restart per beat or per scene. Because it persists, the track started in the main menu carries unbroken into the opening. Output volume is that mix level scaled by the saved music setting.
- `ImpVoice` (`Scripts/Audio/`): the imp's gibberish blip voice, its own audio component listening to `NarratorView.Typed`. It fires a random pitched blip every couple of non-whitespace characters as a line types (colour tags are already skipped upstream), and stops the instant the line ends or is advanced. It is tuned for the current **lower, warmer clips** (the six `imp_voice_*.wav` were replaced in place, same filenames, so the refs hold): a **narrow pitch spread around one** so it reads as a talky mutter rather than a shrill stutter, and a **blip guaranteed on the first revealed character** so the voice never silently drops out. Volume (scaled by the SFX setting), pitch range, and characters-per-blip are exposed. No audio lives in `NarratorView`; it only raises the event.
- `GunSfx` (`Scripts/Audio/`): the gun's single shot, a placeholder gunshot played once on its own AudioSource. It sits on the `Crosshair` (the gun) with an exposed volume (scaled by the SFX setting), and `ShootingConsequence` triggers it (`Fire()`) once on the committed shot, covering both the diegetic aim and the text fallback. Audio stays out of the presenter, the same split as `ImpVoice`.
- Audio assets live under `Assets/Audio/Music/` (the background track), `Assets/Audio/SFX/ImpVoice/` (six placeholder blips), and `Assets/Audio/SFX/` (`gun-shot.wav`, the placeholder gunshot). All are placeholders to swap later.

## Localization
The game is fully localizable and ships **English (default) plus Turkish**, built so adding a language later is just adding one data file. See `decisions.md` (2026-07-09).
- **A lightweight overlay layer, keyed by the English source string.** `Localization` (`Scripts/Localization/`, a static service) turns an English source string into the active language at the moment it is shown. English is the source of truth and needs no file: its copy stays authored **inline** in the ScriptableObjects and the scene beats exactly as before, so English reads byte-identical and nothing is hardcoded past this layer. Selecting another language loads its overlay file and `Localize(source)` returns the translation for a key, falling back to the English source whenever a key is missing, so a partial translation never shows blank. This overlay approach (rather than Unity's Localization package, or re-keying every asset) was chosen to keep the solo-authored Inspector workflow and to avoid disturbing gameplay wiring; the trade-off is that the English copy lives in the data and scenes, not a file, but it still flows through the layer at runtime (see `decisions.md`).
- **Localized at the shared display seams.** Almost all text is routed by localizing inside the few seams every string passes through, so beats and dilemmas need no per-call changes: `NarratorView.Show` / `MeasureWrapped` (all imp dialogue, barks, dilemma prompts and reactions, tier quips, the ending lines), `ChoiceButtons.Present` (choice labels), `StatsView` (heading, bar labels, hint, threshold label), `FloatingFigureText.Show` (the pleas), and the menu / settings / credits label setters. Format strings (the money offers, the nuke jabs) localize the **template before** filling it, so each language keeps its own wording around the `{0}` slots. The handful of directly-drawn readouts (the money total, the country name and population, the walking button's own voice, the three-track and would-you-rather option labels) localize where they set their text. Party ids (`man`, `bear`, `charge`, track routes) are never localized: they are internal matching keys, never shown.
- **Per-language data files, one per language.** `Assets/Resources/Localization/<code>.json` (`en` is implicit; `tr.json` ships). Each file is a flat list of entries parsed by `JsonUtility` (`LocalizationData` / `LocEntry`: `k` = the English source key, `v` = the translation, `area` = a human grouping label ignored at runtime), so any characters, the colour markup (`[amber]`, `[red]`, ...) and the format placeholders survive intact and **each language marks its own words for colour**. Adding a language is two steps: drop `<code>.json` (the same keys, translated) and add one line to `Languages.All` (the code, the native name shown in that language, and the .NET culture for number formatting). Missing keys fall back to English.
- **Numbers and currency route through the layer.** `Localization.Number(n)` groups for the active culture (English `1,000`, Turkish `1.000`) and `Localization.Money(amount)` formats the currency (the `$` prefix kept by default, overridable per language via a `money.pattern` key). The escalating offers, the nuke population readout, the timer countdown, and the stats counts all use these, so amounts read correctly in each language.
- **The runtime language setting.** `GameSettings` holds the language code (persisted in `PlayerPrefs` under `settings.language`) alongside the volumes and fullscreen, and drives `Localization.SetLanguage` on boot. A `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` hook in `Localization` also applies the saved language before any scene loads, so **every** scene respects the choice, including the standalone test scenes and dev-picker jumps that carry no `GameSettings`. The **settings panel** gained a **Language** row: a new in-style `OptionControl` (`Scripts/Settings/`, a labelled left/right cycler in the ink aesthetic, mirroring `ToggleControl`) listing the available languages by their own names (English, Türkçe). Changing it calls `GameSettings.SetLanguage`, which raises `Localization.LanguageChanged`, and the menu and settings **re-localize live** (each label control gained a `Relocalize`; the language row also re-syncs its shown value). The panel frame was enlarged to fit the extra row (its scene instance set explicitly, since a changed code default does not migrate).
- **Turkish font / glyph handling.** The dialogue font, **Caveat** (`Assets/Fonts/Caveat SDF.asset`), is a **dynamic** TMP atlas, so any glyph is added on demand from the `Caveat-SemiBold` source. The source carries the full Turkish set, so the Turkish characters (the dotted/dotless i `İ`/`ı`, the breve g `ğ`, the cedilla s `ş`, plus `ç`/`ö`/`ü` and capitals) render with no missing glyphs; they were also **pre-baked into the committed atlas** (via `TMP_FontAsset.TryAddCharacters`) so they are present from the first frame and in builds. Verified in play: the menu, the settings, and the opening narration all render in Turkish with `missingGlyphs=''` (no boxes).
- **The Turkish content is a first pass.** The imp's voice, its mocking register, and especially the **swearing and the rage-quit / shoot-the-imp / one-dollar break lines** were adapted **idiomatically** (natural Turkish profanity carrying the same force and comedy, not literal translations of the English swears), and want a native-speaker review pass (see `open-questions.md`). The no-dashes rule holds in Turkish too (Turkish-appropriate punctuation).

## Scene, prefab & file structure
Composed from small prefabs, one component (MonoBehaviour) each. No monolithic drawing script:
- `Assets/Scenes/Dilemma.unity` with `DilemmaStage` (`Assets/Scripts/Dilemma/DilemmaStage.cs`) as the composition root for a standalone one-dilemma scene: it validates its wiring, runs the shared `DilemmaRunner` (the explicit Present/Choose/Consequence/Stats/End loop) once, and reloads to replay. The same runner is what a sequenced `DilemmaBeat` plays, so the loop lives in one place.
- `Track` prefab (`Track.cs`): the forking track and the single source of truth for layout; exposes query methods for figure positions and the trolley path so nothing else hard-codes geometry. Its geometry is tuned so the trolley tableau reads **clean and centred** — the fork/lever near centre, the five figures grouped, the trolley in from the edge, all on the rail baseline — rather than drifting to one side. The branch is a schematic **right-angle switch** (the main line runs straight through the fork; the branch drops vertically at the fork then runs straight and parallel below), and the Track drives the figure positions, the rails and cross-ties, and the trolley path (straight, corner, straight) from it. Change the layout here (or the `RoomConsequence` centre for the room, which sits higher in the opening to clear the lifted box) and every instance follows; both trolleys share the Track.
- `Figure` prefab (`Figure.cs`): a clean single-stroke stick figure with rounded joints and no joint dots that folds and fades as one unit. Its death is only the fold-and-fall-and-fade; no strike lines or impact puff are drawn over it (the `PuffCue` cue is no longer used on deaths). `Brand()` recolours the figure's whole outline to a **red** (`Figure._brandColor`, defaulting to `Palette.InkRed`, the button red), marking the branded wretches in the whose-life-counts trolley at a glance (deliberate colour on the ink base, see `art-and-ui.md`); the innocent on the branch stays black. Drawn with a `LineRenderer` for the prototype (the analogue of the earlier Godot `Line2D`) and structured so it can be promoted to a Unity 2D Animation rig (bones and sprite skinning) later, not redrawn.
- `BearFigure` prefab (`BearFigure.cs`, `Scripts/Figure/`): a clean, minimal doodle bear in black ink, front facing and sitting, built from `LineRenderer` ink strokes like the `Figure`: a rounded body (wider than tall), a head circle overlapping it slightly at the neck, two ears drawn as **open arc bumps on the head outline** (not full circles laid over it), a small muzzle, and a **minimal face** (dot eyes, a small nose, a tiny line-and-smile mouth). No arms; two feet as downward bumps whose tops sit on the body's lower edge. **No cub or offspring cue** (dropped in the redesign); the species-extinction weight rests on the imp's words alone. She is filled with a muted **brown** crayon wash inside the outline (`_fillColor` = `Palette.InkBrown`, plus `_fillOpacity`), the same treatment as the blue/red buttons and contained to the bear (a currently experimental colour, see `art-and-ui.md`); the fill fades with the fold. Her head height (`_headCenterY`) and every proportion are exposed tunables. She strikes, folds and fades as one unit with the same death effect as the `Figure` (no strike lines). Used only by the man-and-the-last-bear shooting dilemma.
- `CrownedFigure` prefab (`CrownedFigure.cs`, `Scripts/Figure/`): a `Figure` subclass for Chapter 2's better-offer button, drawing the ordinary stick line plus a small hand-drawn three-point crown, so it inks, brands, folds and fades as one. The beat gold-brands it (`Figure.Brand(Palette.InkGold)`), so the whole figure and crown read gold (gold = the best life; see `art-and-ui.md`). Overrides only the shape.
- `WalkingButton` prefab (`WalkingButton.cs`, `Scripts/Figure/`): the gag figure for Chapter 2's walking-away button, built from ink strokes like the `Figure`. A plain ink push-button that `ComeAlive()` sprouts stick legs, arms and a put-out face onto (with a hurt recoil), then `WalkOff()` strides off the screen (a simple leg-swing walk cycle and a waddle). No death; a joke.
- `Crosshair` and `AimHighlight` prefabs (`Scripts/Aim/`): the first-person gun and its target lock. `Crosshair` draws an ink reticle that follows the pointer (a first-person gun barrel at the lower frame edge is a tunable, `_showBarrel`, now **off by default**, so the point of view reads through the reticle alone) and raises `Fired` at the world point under it; it is the diegetic aim, the analogue of the trolley's `Lever`. It also carries the `GunSfx` (the gun's shot). `AimHighlight` is the single **amber** attention accent of the dilemma: four hand-drawn corner brackets that snap around whichever target the crosshair is over. Both stay pure ink apart from that amber lock, and are driven by the presenter, not by each other.
- `Trolley` prefab (`Trolley.cs`): follows a supplied path with anticipation and a settle on impact; raises an `Impact` event. It can bank to face the path or stay level (`_bankToPath`, off so it stays level through the schematic right-angle switch, not nose-down).

- `NarratorView` (`NarratorView.cs`): the narrator's line as world-space TextMeshPro that inks in (fades while it types on). It draws no chrome itself, but raises `Speaking`, `Typed`, and `HasLine` so the imp, its blip voice, and the `DialogueBox` frame can react; in the opening it renders inside the `DialogueBox`.
- `ChoiceButtons` (`ChoiceButtons.cs`): two plain world-space text choices as the fallback to the lever, picked by click or key.
- `StatsView` (`StatsView.cs`): display-only bars over a dimmed world, the player's pick in amber (minimal UI).

- `ButtonChoice` (`Choices/ButtonChoice.cs`): the blue/red button's two ink buttons, told apart by label alone (the narrator names them); amber on hover and selection only. Raises `Chosen`.
- `InkButton` (`Choices/InkButton.cs`): a reusable single pressable ink push-button (circle plus inner bezel ring, amber on hover, a press squash), built at runtime via `InkButton.Create` and armed for a choice window; raises `Pressed`. Gives every Chapter 2 button beat a real pressable button.

It owns no diegetic input (the player answers through the shared text `ChoiceButtons`) and keeps no per-question state, so one instance is reused by every light question in a sequence; it runs the same `BinaryResolver`, stats and silent profile as the heavy dilemmas.

Prototype implementation notes: all ink is one shared `Sprites/Default` material tinted per stroke (rounded caps and corners, vertex-colour alpha so a stroke fades uniformly). ## Dev tools (editor and development builds only, never ships)
A developer **chapter / beat picker** for testing, so a specific dilemma can be reached without replaying from the top. It is a development tool, not a player-facing feature, and is gated out of shipping builds.
- **`DevChapterPicker`** (`Scripts/Dev/`): a self-contained IMGUI overlay (plain buttons, deliberately **not** in the game's hand-drawn style, since it never ships). It lists the chapters/scenes and, for the loaded chapter, its beats, and jumps to any of them. One script, one job; nothing else references it, so it can be deleted or disabled cleanly.
- **Gated three ways so it can never reach a player.** (1) **Compile-time:** the entire body and the auto-spawn are wrapped in `#if UNITY_EDITOR || DEVELOPMENT_BUILD`, so a normal (non-development) build strips it to an inert, never-instantiated empty component. (2) **Auto-spawn only:** it is created at runtime by a gated `[RuntimeInitializeOnLoadMethod]`, so **no game scene references it** and a shipping build never even creates it (the shipping scenes are untouched). (3) **Runtime toggle:** a `[SerializeField] bool _devToolsEnabled` (default on) switches it off live; `Debug.isDebugBuild` is true only in the editor and development builds, matching the compile gate. With the tool off (a shipping build, or the toggle off), the normal boot (MainMenu, New Game) plays exactly as before.
- **How to open it.** Auto-spawned as a persistent `DontDestroyOnLoad` object, so it is available **from any scene**, including a scene opened directly in the editor. Press the hotkey (`[SerializeField] Key _openKey`, default `F1`; the new Input System's `Key`, since the project is new-input-only) to toggle the overlay, and Esc to close it; a small magenta `DEV TOOLS [F1]` hint sits in the corner while dev tools are on so it is obvious a dev tool is live. No dev button is added to the main menu (to avoid touching that scene); the hotkey covers the menu too. To toggle the flag at **edit time** in the Inspector, drop a `DevChapterPicker` onto a GameObject in a scene: the bootstrap detects the existing one and does not spawn a duplicate.
- **What it does.** Jump to a **chapter/scene start** loads that scene from the top (`Opening`, `ChapterTwo`, the standalone `Dilemma` / `BlueRedButton` / `BearDilemma`, or `MainMenu`). Jump to a **beat** reloads the current chapter entered partway: it sets `SequencePlayer.PendingStartBeat` (a one-shot start index, consumed and reset to 0 on `Start`, inert at 0 so normal boots start from the top) and reloads, then `SequencePlayer` runs a small preamble for a mid-entry (clears the opening black wash and shows the imp, since the skipped intro beats never ran) and plays from that beat through the **real** loop (the imp, the consequence, the stats). Every beat builds its own apparatus (its station / figures), so a mid-chapter jump runs correctly on its own.
- **List source and keeping it in sync.** The chapter/scene list is the **one** hardcoded list, centralised in `DevChapterPicker._chapters`; keep it in sync with Build Settings and the scenes on disk (a scene added there must be added here to be jumpable to). The per-chapter **beat** list is **not** hardcoded: it is read live from the loaded scene's `SequencePlayer.Beats` (a new read-only accessor), labelled by each beat GameObject's name (for example `05_Baby`, `C2_BlueRed`), so it never drifts from the real beat order.
