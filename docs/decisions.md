## 2026-07-11 — Save and continue: one continuous save, auto plus manual, exact-beat resume, New Game overwrite confirm, Esc pause (feat/save-system)
Built the save/continue system that finally enables the main menu's Continue, reusing every existing system (the sequence/beat flow and its `PendingStartBeat` partway-entry, the persistent `Profile`, the `MoneyBalance` + `PurchaseLedger`, the endings, the menu). All hard constraints held (no dashes in any language, no fail state, no scoring or right answer, minimal UI, deliberate colour on the ink base with amber for attention, profile silent, everything localized English + idiomatic Turkish).
- **One continuous save (single slot), the full run state, versioned.** A single JSON file under `Application.persistentDataPath`, robust to missing / empty / corrupt / wrong-version (any of those reads as no save, so Continue is disabled and the game behaves as before). It captures everything a faithful resume needs, not just a beat pointer: the exact **sequence position** (chapter scene + beat index), the silent **profile** tally (stored by axis name, so appending axes never invalidates a save), and the money chapter's **economy** (the balance and the full purchase ledger, bought + skipped, which is also how "poverty ended" and every owned item are carried, since the buyback and receipt read the ledger). A `version` field invalidates incompatible old saves rather than crashing. `SaveData` model + `SaveService` (an auto-spawned persistent singleton, the same shape as `GameSettings`) + `SaveCapture` (the run-state to save-state bridge), under `Scripts/Save/`.
- **Auto-save plus manual save.** Auto-save writes on **entering each beat** (so a quit never loses more than the current beat, which re-plays cleanly since every beat builds its own apparatus); it is cheap (one small JSON per beat boundary, not per frame). ## 2026-07-08 — Design pivot: from a moral trial to the imp's game of no-right-answer questions (feat/design-pivot-docs)
**A docs-only reframe. No gameplay code, scenes, prefabs, or assets changed** — only the markdown in `docs/` and `CLAUDE.md`. **This supersedes the earlier "moral trial" framing throughout:** where older entries or copy describe the game as a trial of the player's ethics, or as a moral-dilemma-only experience, this entry governs.
- **Frame: trial → the imp's game.** The afterlife is no longer a courtroom or a trial of the player's morality. It is the imp's game: he runs the player (still the dead judge, now the one being *figured out* rather than judged) through an ordered stream of questions to work out **who he is** — the whole person, not just his ethics. The irony is kept but reframed: the man who spent his life sizing up everyone else is now the one being sized up. The DUI stays a light recurring gag (unchanged). The payoff still points at the player: who *you* are, read through this character.
- **Content rule widened.** The only criterion for a question is that it has **no right answer** *and* it **divides people or reveals something about the answerer**. Dropped the "moral dilemmas only" framing: all question types are in scope (would-you-rathers, preferences, taste, absurd hypotheticals, confessions, and genuine dilemmas). Questions with an obvious consensus answer are cut, because the "how others chose" reveal is dead if everyone picks the same thing.
- **Mix: mostly light, heavy as spikes.** The light and medium questions are the volume; heavy dilemmas are rare, spaced spikes, paced in waves so a heavy one lands harder after a run of light ones. Tone stays dark comedy but playful: the imp gives the profound and the idiotic the same ceremony, and his single voice ties the range together.
- **Profile broadened to a "who you are" portrait.** From moral-only axes to a small set of characterful axes where **neither pole is the good one** (first pass: head vs. heart, self vs. others, order vs. chaos, risk vs. safety, honest vs. kind; aim four to six, still open). Both heavy and light questions can nudge them; **not every question feeds the profile** (pure-taste questions exist just for the fun and the crowd stats). The earlier moral axes (one vs. many, mercy vs. justice, ends vs. rules, order vs. freedom) **fold in** as the ethics-flavoured part, still used by the heavy dilemmas. Still silent, never a running gauge. The rejected selfish↔selfless framing still stands (no axis where one pole is simply "the good person").
- **Stats promoted to the central hook.** "How others chose" is now a central pillar, front and centre: every question ends on the crowd split as a real beat. - **Structure: linear, multiple profile-based endings.** One ordered run through a curated set of questions with the imp between them; the path is the same for everyone. Each verb has a `VerbResolver` (`BinaryResolver`, `CoordinationGambleResolver`; `Allocation` and `SelfSacrifice` are stubbed seams) that turns the choice plus the seeded crowd into a `DilemmaOutcome` (which parties fold, the narrator reaction, and a `ResolutionReport` for the stats). A per-verb `ConsequencePresenter` (`TrolleyConsequence`, `CrowdConsequence`) owns the scene apparatus and the animated consequence. `DilemmaStage` now only resolves, plays, reveals, and records, with no verb branches. The trolley was refactored onto the Binary resolver plus `TrolleyConsequence` with no behaviour change (both outcomes re-verified: divert folds the one, do nothing folds the five).
- The stat is load bearing here, not reflective. `StatsView` is now driven by a `ResolutionReport` and draws an optional threshold marker (the line the crowd had to cross), so the seeded fraction inks in as the number that decided the outcome. The trolley keeps its reflective "how others chose" bar.
- Profile impacts (first pass, silent, tunable): hold the line leans order and control (OrderVsFreedom toward order); roll the dice leans freedom and trust in the many (OrderVsFreedom toward freedom, OneVsMany toward the many). Recorded silently and never drawn; verified.
- Fold-in fix: raised `NarratorView`'s default typing speed so the opening line lands a touch quicker (it was about five seconds). The instruction read "lower the typing speed"; I took the intent to be a faster read, so raised chars-per-second. One tunable value if that was the wrong reading.
